# 数据契约(占位)· 活动记录生成器

> ⚠️ **这是占位契约,不是权威 schema。** 「一条 CO 活动」的真结构由 **Creative OS 侧**定;本组件先用占位跑通渲染+导出。
> CO 真 schema 落地后,只需在「输入」层写一个映射函数把 CO 活动 → 下面的形状,后续(每日聚合/渲染/PDF)不用动。
> 本文件只描述**当前组件吃什么、吐什么**,供 CO 对齐用;不构成对 CO 的约束。

## I/O 一句话

**进** = 活动数组 `Activity[]` → **出** = 统计(`computeStats`)+ 月历留痕(SVG,整年/单月/可嵌入小件)+ 印刷级 PDF(`exportRecordPDF`)。
纯 render+export 组件:不自建存储、不写库、无副作用。

---

## 输入:`Activity`(占位)

```ts
type Activity = {
  id:    string;              // 唯一 id
  date:  string;             // 'YYYY-MM-DD'
  type?: string;              // 活动分类;自带 design|writing|research|build|publish,**其余任意值也收**
  title: string;             // 一句话(当天详情/单月页显示)
  weight: number;            // 当日投入/产出量(占位 1..3),聚合后决定着墨深浅
  milestone?: boolean;       // true = 出版级里程碑 → 走朱砂印通道
  [k: string]: any;          // 其它字段原样带着;统计可按任意字段分组(见下)
};
```

`type` 里 `publish` = 里程碑级(出版/上线/展出);其余四类是常规活动,各配一枚矿物分类色。

**类型是开放的**(2026-08-19 起):自带 5 类之外的 `type`(如 `meeting`/`复盘`)会**自动补进分类表**,
配一枚从矿物扩展色里按类型名派生的颜色 —— 同一批类型名拿到同一套颜色,与出现顺序、次数无关。
没写 `type` 的活动统一归 **`(未分类)`**。这条很重要:**渲染与统计共用同一个类型口径**,
所以不会出现「统计算它有痕、图上那天却空白」的静默丢格。

**「多人」怎么接**:占位契约不含 `actor` 之类字段,组件也不强加。但只要你的活动上带了这种字段,
`computeStats(acts, { groupBy: 'actor' })` 就能按它分组;字段缺失的落到 `(未标注)`。

## 派生:每日契约序列(借 react-activity-calendar 的形状,只借形状不引库)

`toDailySeries(activities, year)` → 把活动按天聚合成:

```ts
type Daily = {
  date:  string;   // 'YYYY-MM-DD'
  count: number;   // 当日 ∑weight
  level: number;   // 强度档 0..MAX_LEVEL(=4)
  dominant: string; // 当天投入最多的 type(决定格子取哪枚分类色)
  note:  string;   // 当天第一条活动标题
  milestone: string|null; // 里程碑标题(有则朱砂印)
};
```

**level 三条硬规则**(`src/data/activity.js` 的 `levelFor`):

| 规则 | 条件 | 结果 | 画面 |
|---|---|---|---|
| 留白 | `count = 0` | `level 0`,不落格 | 素纸留白(讲"没做 / 远行") |
| 墨深 | `count > 0` | `level 1..4` | 分类色/墨色由浅到深 = 投入由少到多 |
| 里程碑 | `milestone === true` | 另走朱砂通道,**不占 level** | 朱砂印(红方块+内白框+纸色晕+楷体签) |

分档抗离群值:投入量是小整数时**投入量即档**(1→浅…4→深);跨度大时才线性缩放到 `1..4`。

**几条口径(渲染与统计共用,不可能分叉)**:

- **只有 `milestone === true` 才盖印**。`type === 'publish'` 只是普通分类,**照常落墨**
  (2026-08-19 修:此前出版类被排除在墨格外,没打里程碑标的出版活动会在图上凭空消失、统计里却算着)。
- **里程碑有没有,与它叫什么,是两回事**:没写标题的里程碑照样盖印(只是不写签)。
- **投入量** `weightOf`:非数字算 0,**负数算 0**(负数本来就画不出来,若带进统计会出现「总投入 5.6、分类合计 0.6」的自相矛盾)。
- **日期**必须是 `'YYYY-MM-DD'` 且真实存在(`2026-02-30`、`2026-13-45` 都不算)。
- **只算当年**:别年的活动既不落格,**也不参与 `maxWeight`**(否则去年一条超大投入会把今年的墨深整体压平)。
- 上面两条被挡下的活动**不会被悄悄吞掉**:`stats.dropped` / `model.dropped` 里有
  `{ invalidDate, otherYear, malformed }` 计数,调用方可以据此提示用户。
- **同一天多类型投入打平**时按类型名排序定胜负 —— 同一份数据换个数组顺序不会换颜色(输出确定)。

## 派生:渲染视图模型

`toRecordModel(activities, year, variant)` → `renderRecord` / `buildRecordPdfBytes` 共用:

```ts
type RecordModel = {
  year: number; variant: string;
  categories: { id, name, color, render }[];   // 由 PALETTES[variant] 上色
  days: { [date]: { categoryId, count, level, intensity, note } }; // level 0 的天不在此(留白)
  milestones: { date, label }[];               // 朱砂印通道
  maxWeight: number; maxLevel: number;
};
```

`intensity = level / maxLevel` 是渲染唯一强度真源(墨色透明度由它算)。

## 派生:统计(`src/data/stats.js`)

`computeStats(activities, { year, from, to, groupBy })` → 与渲染**同源**的派生统计(内部复用 `toDailySeries`,
所以图上落格几天、统计就说几天,不会有两套数字):

`from`/`to`(含首尾)只统计那一段 —— 秘书交的是「这周 / 这个月」的账。
助手 `monthRange(year, m)` / `daysBack(endDate, n)` 都是纯函数,**组件不看时钟**,基准日由调用方给
(否则同一份数据今天明天出不同结果,组件就不确定了)。强度分档仍按**全年**尺度算,
所以「墨深」在区间内外含义一致。

```ts
type Stats = {
  year, activities,                                  // 年份、纳入统计的活动条数
  range: { from, to, days, whole },                  // 这次算的是哪一段;whole=true 表示整年
  days:   { total, active, blank, rate },            // 全年天数(闰年自动)/有痕/留白/占比
  weight: { sum, max, avgPerActiveDay },
  streak: { longest, longestFrom, longestTo, latest, latestFrom, latestTo }, // 最长/最近连续
  byType: { id, name, count, weight, days, share }[],// 按投入降序
  byMonth: { m, name, days, weight, count, dominant }[], // 定长 12
  levels: number[],                                  // 强度分档分布(下标 0..4)
  busiest: { date, count, level, note } | null,
  milestones: { date, label }[], firstDate, lastDate,
  groupBy?, groups?: { key, count, weight, days, milestones, share }[], // 给了 groupBy 才有
};
```

`summarize(stats)` → 一行人话摘要(秘书交差用)。空/null/非数组输入一律安全归零,不抛。

## 输出

- `renderRecord(model,{variant,texture})` → SVG(整年 12 月行×31 日列 A1 长条)。
- `renderMonth(model,m,{variant,texture})` → SVG(单月详情卡,210×280mm)。
- `renderStrip(model,{...})` / `renderStatCard(stats,{...})` → **可嵌入小件** SVG(侧栏/仪表盘用,
  同页可放无限个:滤镜 id 按内容派生前缀不撞车,一律 `width="100%"`+viewBox 由容器定尺寸)。
- `exportRecordPDF(activities, year, variant)` → 印刷 PDF(A1+3mm 出血+裁切标+CMYK+子集嵌字+拓质≥300dpi 位图)。

**手工质感**(`src/texture/index.js`):`rubbing` 拓质 / `tiedye` 扎染 / `handdrawn` 手绘 /
`topographic` 拓扑 / `none` 素纸,每个参数可改;所有渲染与印刷栅格化共用同一份定义。
参数规则只有一条:**按 A1 长条为基准写,载体只换算噪声频率**,故同一份配置到哪个载体都一个样。

## 变体

| variant | 皮肤 | 里程碑 | 类型着色 |
|---|---|---|---|
| `editorial-rubbing`(B,默认) | 暖·编辑 + 拓质 | 朱砂印 | 暖分类色,强度→透明度 |
| `tuogu-ink`(A) | 全拓·单色墨 | 朱砂印 | 不着类型色,只用墨深 |

## ⚠️ 待 CO 对齐点(真 schema 落地时改这里)

1. **`type` 枚举** —— **已不再是硬约束**:自带 5 类之外的任意类型都能吃(自动补分类+派生配色),CO 分类更多/不同也不会丢数据。
   仍待 CO 定的是**要不要给常用类给定名与定色**(给了就写进 `ACTIVITY_TYPES` + `PALETTES`,不给就吃派生色)。
2. **`weight` 语义** —— 现占位「投入量 1..3」;CO 若用时长/产出数/自评分 → 只改聚合入口,`levelFor` 的分档逻辑可复用。
3. **`milestone` 判定** —— 现占位**只认 `milestone === true`**(`publish` 只是普通分类);CO 若有独立"里程碑"字段 → 改 `aggregateByDay` 的取值。
   附:**「谁做的」这类字段** —— 组件不强加,但带上就能 `groupBy` 统计(见上)。CO 若要按人出图,建议统一字段名。
4. **`title`** —— 现占位一句话;CO 若有富结构(链接/封面) → 单月详情页可扩展显示,整年图仍只取一句。
5. **时间范围** —— 现占位单年;CO 若要跨年/任意区间 → 版面几何(`layout.js`)需相应参数化(暂不做,等 CO 定)。

**映射建议**:CO 真数据来时,写 `fromCreativeOS(coActivities): Activity[]` 一个纯函数塞在输入层,组件内部一律不动。这样"接进 CO"= 加一个 adapter,不改渲染/导出。
